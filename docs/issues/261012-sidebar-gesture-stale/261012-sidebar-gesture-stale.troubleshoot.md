# 侧栏手势状态残留导致误开侧栏 排查 (261012-sidebar-gesture-stale)

> 日期：2026-10-12
> 状态：根因已锁定并经状态机回放复现，确信度高

## 1. 现象描述

偶现：用手势把侧边栏滑关之后，手势状态没有正常结束，之后在界面上任意拖动会把侧边栏重新打开（或产生其它非预期的开合）。用户猜测与卡顿导致触摸事件丢失有关。

## 2. 复现

`installGesture` 是纯状态机，依赖 `window` 上的 touch 事件。用抽离真实函数源码 + 桩 DOM 的方式回放触摸序列（含"故意不派发 touchend"以模拟丢事件），在修复前确定性复现：

- 用例 [1]：`touchstart(100,300)` 记录手势（dx 未过阈值）→ **touchend 丢失** → 下一次 `touchstart` 落在输入框（`gestureShouldSkip` 命中，直接 return）→ 该次拖动仅移动 100px，却相对**旧起点**计算 dx=100 ≥ 64 → 触发 `toggleSidebar`。
- 用例 [2]：同上丢结尾事件，后续双指 move 复用同一 `identifier` → 同样误触发。
- 用例 [3]：手势进行中关闭该功能（属性被移除）→ `touchmove` 不校验属性，仍会触发一次开合。

## 3. 根因分析

手势生命周期原本只有一条结束路径：

```js
var onTouchEnd = function () { drag = null; };
var onTouchCancel = function () { drag = null; };
```

而 `drag` 是整个安装期唯一的模块级状态，只在 touchend / touchcancel 时清空。一旦这两个事件丢失（卡顿被合并丢弃、应用切后台、渲染进程冻结等），`drag` 会**永久处于已武装状态**：

1. `onTouchStart` 在 `event.touches.length !== 1`、`modalOpen()`、`t.clientX < EDGE_IGNORE_PX`、`gestureShouldSkip(target)` 任一条命中时提前 return，**不会**清理旧状态——落在输入框、代码块（横向可滚动）等被跳过的区域时，残留的 `drag` 被原样保留；
2. `onTouchMove` 只用 `t.identifier !== d.id` 做校验，而移动端触摸 `identifier` 会从 0 复用，新手指的 move 事件因此匹配上旧手势，`dx/dy` 全部相对**旧起点**计算，很容易瞬间越过 64px 阈值；
3. `onTouchMove` 也不校验功能属性，功能关闭后已武装的手势依旧会触发。

即：**手势状态只由"结尾事件"终结，且被信任地用于后续任意一次拖动**。这正是"随便拖动就把 sidebar 打开了"的直接原因（用户滑关时/之后的那次 touchstart 记录的 `open=false`，残留后任何一次 ≥64px 的右向拖动都会命中 `!d.open && right` → 打开）。

## 4. 修复路径（单点修复）

把手势状态改为"**每次事件都重新验证活性**"，而不是依赖唯一的结尾事件：

1. `endGesture()` 统一收口 `drag = null`；
2. `onTouchStart` **第一行**无条件 `endGesture()`——新触摸即代表此前手势已结束（无论该次触摸是否会被跳过）；
3. `onTouchMove` 校验三件事后否则清状态并返回：`event.touches.length === 1`（仍只有本手势的手指）、`t.identifier === d.id`、功能属性仍为 on；
4. 新增 `blur` / `pagehide` / `visibilitychange` 时的清理，覆盖"切后台不给结尾事件"的场景；
5. disposer 中一并注销新增监听并清空状态。

不引入时间窗/超时等启发式规则（会误伤慢速滑动的正常手势），只用浏览器给出的活跃触摸列表做权威校验。

## 5. 置信度与验收标准

- **置信度**：90%+。三个失败用例在修复后确定性通过，8 项既有行为回归全部通过；剩余不确定来自真机事件时序（丢事件的真实形态无法在桩环境完全还原）。
- **验收标准**：
  1. 侧栏关闭时全屏右滑 >64px 正常展开；展开后左滑 >64px 正常收起；反方向滑动不误触发；
  2. 竖直滑动不抢滚动；输入框内、横向可滚动区域内不触发手势；
  3. 滑关侧栏后，在输入框/聊天区任意拖动**不会**再打开侧栏；
  4. 手势进行中切后台再回来，不会复现误触发。
