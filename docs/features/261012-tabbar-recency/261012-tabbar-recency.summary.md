# 标签栏「最近活跃」改为纯活跃时间排序 — 总结

日期：2026-10-12 · 状态：实现完成，语法校验通过，待用户实机验收

## 需求（用户 2026-10-12 提出）

> 标签栏，不再要根据颜色的排序

口径：Tab Bar 的「最近活跃」模式此前把页签**按状态色点分组**（黄 = 待处理 / 绿 = 完成未读 / 蓝 = 运行中 → 整体排前；灰色空闲排后），组内再按活跃时间。用户要求**去掉颜色分组**，只按活跃时间排序。状态色点仍照常显示，只是不再影响位置。

## 交付内容

1. `lib/client.js` — comparator：删除 `rankOf`（`pendingOf / unreadOf / runningOf → 0`，其余 `→ 1`）分级；非固定区直接 `updatedAt` 降序（最新最左）。固定区规则不变（按 pin 顺序置顶）。`handleClose` 的落点逻辑无需改动：它取剩余页签中 `updatedAt` 最大者，与新的排序方向一致。
2. `lib/client.js` — 文案同步：FEATURES 行 hint 与设置页模式说明改为「按活跃时间排序，最新最左；状态色点只作提示、不影响排序」。
3. `README.md` / `README.en.md` — Tab Bar 行的模式说明同步（去掉「黄/绿/蓝整体排前、两区内最新最左」）。
4. `e2e/tabbar-mode.mjs` — 断言同步：hint 文案断言改「按活跃时间排序」；E 段排序断言由「按色点分组」改为**统一**的纯活跃度断言（页签在侧栏中的位置从左到右严格递增，与有无色点无关，色点只在 E2 段验证「活跃 → 左移」）；E2 段标题/断言语义改为「最旧的两个页签收到活动后左移」。

## 验证

- `node --check lib/client.js` / `node --check e2e/tabbar-mode.mjs` 通过。
- 未跑 e2e（全量 GUI e2e 会真实发消息触发 LLM，3~6 分钟/次）：按既有约定由用户在 4180 刷新实机验收。

## 影响

- 「最近活跃」与「标准」的差异收敛为：**活跃时间序 vs 打开顺序**。固定区语义、关闭/落点语义、色点显示均不变。
- 260925 的「彩色区优先级」规则自此废止（原 doc 已加注指向本文）。
