# tabbar-width 验证

## 验证说明

- 验证对象：标签尺寸放大、Chrome 式自适应宽度、取消 12 标签上限、关闭延迟重排（触屏立即重排）、移动端 96px 下限、非活动标签隐藏关闭按钮且活动标签相应加宽、关闭后激活右侧标签
- 环境：Windows 11 + dsh 0.2.1-rc.3；桌面端手测，另起临时 `dsh --profile web` 实例做 390×844 触屏视口验证
- 方法：临时实例用 `dsh plugin --profile web add link:<repo>` 挂本仓库；标签数量用 `dsh.qol.opentabs` 预置；宽度用 `getBoundingClientRect()` 与 `scrollWidth` 直接测量；视口由 CDP 设为 390×844 / DSF 3 / 触屏
- 注意：验证用的是本仓库 `lib/client.js`，不是 npm 已发布版本

## 宽度与文本的换算

标签的固定开销约为 36px（左右内边距 24 + 状态点与间距 12），关闭按钮约占 20px，因此：

| 标签宽度 | 非活动标签标题区 | 大约可见 |
| --- | --- | --- |
| 72px | 36px | 1 个字 + 省略号（早期版本） |
| 88px | 52px | 2–3 个字 |
| 96px（当前移动端下限） | 60px | 4 个字 |
| 110px | 74px | 5 个字 |

活动标签保留 ×，在窄屏下于宽度上补回 24px（96 → 120），所以它的标题宽度与非活动标签基本相同；宽屏不做隐藏与补偿，所有标签等宽且都带 ×。若希望手机上显示更多字，只能继续提高下限，代价是一屏能放下的标签数减少（390px 下 96px 约 3 个，110px 约 2–3 个）。

## 验证结论

自适应宽度、取消数量上限、鼠标延迟重排、触屏立即重排、移动端 96px 下限、「窄屏隐藏非活动标签 × + 活动标签加宽」「宽屏保留所有 ×」以及「关闭后激活右侧标签」均按设计工作；390px 下非活动标签可以完整显示 4 个汉字。
